## How it works

```
TV (ADB, Android TV Remote, Cast) ──> HA ──> umote integration ──> sensor.umote_sources / sensor.umote_home / image.umote_artwork
                                                                           │ (ESPHome homeassistant text_sensors)
                                                                           v
                                                         remote: ui_lv.h renders 4 pages (TV / Soundbar / Home / Settings)
remote taps/keys ──> homeassistant.action (umote.launch, remote.send_command, fan.*, homeassistant.*) ──> HA
soundbar keys ──> IR (Sony SIRC)            TV off ──> Wake-on-LAN (<tv_mac>)
```

**HA side** (`ha/custom_components/umote/`)
- `tvparse.py`: inputs (HW id ↔ HDMI port ↔ CEC name) and launcher apps from `dumpsys tv_input`, `dumpsys hdmi_control`, `cmd package query-activities`.
- `sources.py`: ordered list (connected inputs, Live TV, apps by use), quick row (top 4 + current), "More apps" (unused 30 days).
- `home.py`: Living Room tiles from the registries (fans with LED/speeds/timer, light and switch groups, Matrix clock as display).
- `artwork.py`: Cast artwork to a 212×76 baseline JPEG ≤ 16 KB.
- `coordinator.py`: reads the TV through `androidtv.adb_command`; keeps the last inputs/apps in `Store("umote.tv")` so the list survives restarts with the TV asleep; refreshes on remote state change and when ADB comes back after a wake; counts usage.
- Services: `umote.launch {source_id}` (wake wait, HOME, then passthrough URL or app), `umote.name_source {port, name}`.
- **Attributes are JSON text**, not lists: HA forwards attributes to ESPHome as `str(value)`, which turned lists into Python reprs the remote couldn't parse.
- Deploy: `ha/deploy.sh` (SSH add-on, `ha core check && ha core restart`).

**Firmware** (`firmware/`)
- `logic.h`: pure, host-tested: key routing per page (spec §4.4), TV view choice, progress, staleness, text sanitising for the font, ellipsis, Wi-Fi scan parsing, backlight floor. Tests: `g++ -std=c++17 -Wall -Werror firmware/test/test_logic.cpp`.
- `ui_lv.h`: the whole LVGL UI in C++ at the mockup's pixel positions (`docs/superpowers/specs/2026-10-30-remote-ui-assets/all-screens-v5.html`). Sheets, the page picker, Wi-Fi/About views and the keypad are **built when opened and freed when closed** (boot UI heap 124 KB → 47 KB in the sim).
- `ui.yaml`: tileview pages, settings globals (restored), hooks into the device scripts, `ui_rev` stamp.
- `assets.yaml` + `assets/`: Inter 12/13/14/15/17/20 (regular, bold, semibold), 41 SVG icons at the sizes used, 13 app icons pulled from the TV (`tools/appicons.py`).
- `ui_res.yaml`: generated by `firmware/tools/gen_res.py` from `assets.yaml`; regenerate after changing assets.
- `remote.yaml`: HA bindings, key routing (`press` → `umote::route`), WoL, soundbar IR table (`soundbar_ir`), Wi-Fi scan/join, Keep awake, RTC data cache, debug sensors, sleep.

## Shipping firmware (read this before installing)

1. `FORCE=1 firmware/deploy_to_ha.sh` copies everything to `/config/esphome/tv-remote.yaml` + `/config/esphome/tv-remote/`, rewriting paths and **stamping `ui_rev` with a hash of `logic.h` + `ui_lv.h`**. The builder only rebuilds when the YAML changes; without the stamp, header-only fixes re-flash the old binary ("Build configuration is up to date").
2. Install from **HA → ESPHome Builder → tv-remote → ⋮ → Install → On the network**. It compiles on the user's Windows build server ("NavazdeenS").
3. The remote must be awake: **Settings → Keep awake** (10 min, WiFi on, no deep sleep). The builder's "install when it comes online" queue did not fire in practice.
4. **Never OTA a local build.** `firmware/secrets.yaml` here holds placeholders; flashing one cost the remote its WiFi once (recovered over USB). Local builds are for compile checks only.
5. Check: HA device info shows the new build time; `sensor.living_room_tv_remote_reset_reason` / `_free_heap` / `_largest_free_block`.

## Problems hit on the device, and the fixes

| Symptom | Cause | Fix |
|---|---|---|
| New firmware "installed" but old UI back | ESPHome safe_mode marks a boot good after 60 s; the remote deep-sleeps after 6-20 s, so every OTA rolled back | `safe_mode: boot_is_good_after: 10s` |
| Still rolled back | Out of memory: whole UI built at boot (~124 KB) on a no-PSRAM ESP32 | Build sheets/views on demand |
| Still rolled back | `ui_refresh` at on_boot 800 and the battery sensor touched widgets before LVGL built them | `ui::ready` guard on every entry point |
| Brightness slider blacked the screen | 10 % allowed and saved | Floor 30 %, clamped where applied (`umote::backlight_level`) |
| Wi-Fi scan empty | `get_scan_result()` empty while retrying a network | `wifi_info: scan_results` sensor + `umote::parse_scan_text` |
| No sources / "Back to TV" did nothing | HA sent Python reprs, not JSON | JSON-text attributes |
| Stuck in device options / page picker | Only the hardware Back key closed sheets | Tap on the dimmed backdrop closes any sheet |
| Fan + stuck at 1, tap went to the Matrix clock | Options sheet held its tile by list index; HA re-sorts tiles | Holds the tile id |
| Garbled big app icon + log flood | LVGL can't scale RGB565+alpha | Icons never scaled |
| HTTP 500 artwork fetches (~48 KB each) | Fetched with nothing playing | Only while Cast reports playing/paused with a title |
| Overlapping views on every wake | TV page's three views visible until first data | "Connecting…" until data |
| Always "Connecting…" | WiFi+HA reconnect outlasts the screen timeout; each wake is a fresh boot | Last HA data in RTC memory (5.9/8 KB), shown dimmed "Updating…"; screen stays ≥ 15 s while HA connects |
| "Last seen" during playback | A log viewer disconnecting reset the HA flag | Freshness follows `is_connected_with_state_subscription()` |
| Green LED on in deep sleep | IO16/IO17 (green/blue) are on VDD_SDIO, powered down in sleep | `esp_sleep_pd_config(ESP_PD_DOMAIN_VDDSDIO, ON)`. **Not yet confirmed by the user** |

## Decisions taken along the way

- UI written in C++ (`ui_lv.h`) instead of YAML; widget names keep the plan's ids for the validator.
- Scrub strip is a 212×44 hit area (a 16 px `lv_slider` fails the 44 px rule); position extrapolated from receipt time.
- Never-used apps are not collapsed into "More apps" until 30 days after first seen.
- Fan timer offers Off / 1 h / 3 h / 6 h (Atomberg supports Off, 1, 2, 3, 6 h; the mockup's 4 h doesn't exist).
- OK short = OK, held ≥ 500 ms = options (Home).
- "Stale" means HA disconnected for 30 s, not "nothing changed".
- Every UI hook does nothing until `ui::ready`.
- Full rulings list: `.superpowers/sdd/remote-ui-ha/progress.md` (gitignored ledger).
